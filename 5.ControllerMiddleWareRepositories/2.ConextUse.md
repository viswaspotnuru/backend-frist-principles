In the video **[10. What are controllers, services, repositories, middlewares and request context?](https://www.youtube.com/watch?v=hyc-7w3pee8)**, Srini explains that a **Request Context** is a scoped, shared state that lives for the duration of a single HTTP request. It allows different parts of your backend—like middlewares and handlers—to share crucial information without being tightly coupled.

### **Why Request Context is Helpful**
* **Scoped Storage [51:54](http://www.youtube.com/watch?v=hyc-7w3pee8&t=3114):** Each incoming request gets its own isolated context. This ensures that metadata for *User A* (like their ID or permissions) never leaks into the processing flow for *User B*.
* **Decoupling Function Boundaries [53:02](http://www.youtube.com/watch?v=hyc-7w3pee8&t=3182):** A request passes through multiple layers (Middlewares → Router → Handler). The context acts as a "storage container" that follows the request through these boundaries. For example, an **Authentication Middleware** can verify a token and save the `user_id` in the context; later, the **Handler** can simply pull that `user_id` out to perform database operations [55:57](http://www.youtube.com/watch?v=hyc-7w3pee8&t=3357).
* **Shared State [58:01](http://www.youtube.com/watch?v=hyc-7w3pee8&t=3481):** It provides a key-value store accessible by any execution environment involved in that specific request's lifecycle.

### **Crucial Information Stored in Context**
Srini highlights several real-world examples of data managed through the request context:

| Information | Use Case |
| :--- | :--- |
| **User Identity [55:57](http://www.youtube.com/watch?v=hyc-7w3pee8&t=3357)** | Storing `user_id`, `role` (Admin/User), and permissions after a successful login. |
| **Request IDs (UUIDs) [58:25](http://www.youtube.com/watch?v=hyc-7w3pee8&t=3505)**| Generating a unique ID at the entry point to trace a request across logs and microservices (Distributed Tracing). |
| **Cancellation Signals [59:33](http://www.youtube.com/watch?v=hyc-7w3pee8&t=3573)**| Sending "abort" or "deadline" signals to external services so the server doesn't hang indefinitely if a request is cancelled. |


### **Security Benefit [56:51](http://www.youtube.com/watch?v=hyc-7w3pee8&t=3411)**
By taking information like `user_id` from the secure **Request Context** (populated by your Auth Middleware) rather than trusting a payload sent by the client, you prevent malicious users from spoofing other accounts.
